# pbzmp 游戏通道（GAME 负载）v1

服务器只转发 GAME 包，不解析负载（见 docs/pvp-protocol.md）。本文件规定负载格式和客户端算法，实现在 `mods/pvp/src/net/`。整数小端，f32 为 IEEE 单精度。

## 包格式

```
u8  gver = 1
u8  flags        保留，0
u16 session      发送方每次进房间随机生成；对手的 session 变了，就把他的通道、字符串表、时间线全部重置
u16 seq          发送方每包 +1
u32 tSend        发送方毫秒时钟（QueryPerformanceCounter 换算，进程内单调）
之后是若干节，直到包尾：u8 type, u16 len, u8 data[len]。不认识的 type 按 len 跳过。
```

| type | 名称 | data |
|---|---|---|
| 1 | STATE | 本地玩家状态（下表） |
| 2 | SURE | u16 id, u16 age, 事件字节 |
| 3 | QUICK | u16 id, u16 age, 事件字节 |
| 4 | ACK | u8 slot, u32 tEcho, u16 hold, u16 next, u32 bits |

- age：事件（或 STATE 采样）到本包发出的毫秒数。发生时刻 = tSend − age（发送方时钟）。
- ACK：每个对手一节。tEcho = 最近收到的该对手包的 tSend，hold = 收到那个包到现在的毫秒数。对方据此算 RTT = 现在 − tEcho − hold，不需要单独的 ping 包。
- next/bits 确认 SURE：id < next 的全部收到；bits 第 i 位表示 id = next+1+i 已收到。id 为 u16，比较时按回绕处理。
- 单包 ≤ 1192 字节。每包都带 STATE（有的话）和 ACK；SURE 和 QUICK 合计 ≤ 900 字节，放不下的留到下一包。

## STATE（49 + extLen 字节）

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u16 | age：采样到发包的毫秒数 |
| 2 | f32×3 | pos：胶囊体中心，世界坐标，cm |
| 14 | i16×3 | vel：cm/s，截断到 ±32767 |
| 20 | i16×2 | acc：输入加速度方向 xy × 10000，0 表示没有输入 |
| 24 | u16 | yaw：0..65535 对应 0..360° |
| 26 | u8 | mode：CharacterMovement 的 MovementMode |
| 27 | u8 | flags：bit0 落地，bit1 锁定中，bit2 架势，bit3 冲刺，bit4 已倒下，bit5 无敌 |
| 28 | u16 | hp：千分比 |
| 30 | u16 | posture：千分比 |
| 32 | u16 | montage：字符串 id，0 = 没有 |
| 34 | u16 | montPos：毫秒 |
| 36 | i8 | montRate：播放速度 × 32 |
| 37 | u8 | armed：0/1 |
| 38 | u8×7 | anim：上层自定义，网络层不解释 |
| 45 | u8×3 | 保留，0 |
| 48 | u8 | extLen：附加数据长度，0..255 |
| 49 | u8×extLen | ext：上层自定义的每帧附加数据，网络层不解释、不插值 |

节长度 = 49 + extLen。长度不符的 STATE 节整节丢弃。

## 两条事件通道

- SURE：可靠、有序、只交付一次。未确认的事件每包都重带（事件很少），收到 ACK 后删除。接收方按 id 顺序交付，乱序到达的先缓存。
- QUICK：不可靠、只交付一次。同一事件连续放进 3 个包，接收方按 id 去重；按时间线算已经晚了 250 ms 以上的直接丢弃。
- 事件内容对网络层是不透明的字节（上层约定为 UTF-8 文本），唯一例外是下面的字符串定义事件。

## 字符串表

蒙太奇、技能类、武器配置、标签这类长路径只传一次，之后用 u16 id 引用。

- 发送方 `Intern(文本)`：第一次见到的文本分配下一个 id（从 1 开始），并自动发一个 SURE 事件 `\x01 <id 十进制> <文本>`（首字节 0x01，网络层自己处理，不交给上层）。
- 接收方按发送方维护表。STATE 里引用的 id 还没定义时当 0 处理。SURE 有序，所以同一通道里排在定义之后的事件一定能查到。
- 对手 session 变化时清空他的表；自己重进房间时 session 换新，表从头开始。

## 发送节奏

- 上层每帧调用一次 `SetLocalState`。网络层按 60 Hz 发包（距上次发包 ≥ 16.6 ms）；有新的事件排队时立即发（两包之间至少 4 ms）。
- 每包内容：最新的 STATE（带 age）、每个对手的 ACK、所有未确认的 SURE（旧的在前，放得下多少放多少）、待发的 QUICK。

## 时间线（接收端）

目标：把对手按他自己的时间顺序、在一个尽量小又够稳的延迟后回放。

1. 每个 STATE 样本的发送方时刻 ts = tSend − age。到达时记本地时刻 tr（接收线程打时间戳）。偏差 o = tr − ts。
2. 基准 B = 最近 3 s 内 o 的最小值（最快的那条路）。抖动 J = 最近 3 s 内 (o − B) 的 95 分位。
3. 目标延迟 D* = clamp(J + 发送间隔 + 8 ms, 25 ms, 300 ms)。D 升高时立即跟上，下降时每秒最多降 10 ms，避免来回抖。
4. 回放时刻（发送方时钟）r = 本地现在 − B − D。取 r 两侧的样本插值：位置用带速度的 Hermite 插值，yaw 走最短弧，hp/posture 线性，其他离散字段取前一个样本。
5. r 超过最新样本：按速度外推，最多 150 ms，之后原地保持，并在统计里记一次“断粮”。
6. 事件也放在同一条时间线上：发生时刻 te 换成本地 te + B + D，到点才交付给上层，这样技能和位移对得上。SURE 事件要按序，前面的没到点后面的也等着；已经过点的立即交付。

## 统计

每个对手提供：RTT（平滑值和最近值）、B、J、D、每秒收包数、丢包率（按 seq 缺口算）、断粮次数。界面上显示 RTT，测试脚本用其余几项。

## 链路测试

`mods/pvp/src/net/nettest.cpp`（控制台程序）起两个客户端连到服务器（服务器可加 `--loss --delay --jitter` 模拟坏网），A 端沿合成轨迹（直线、急停、转圈、冲刺）运动并发事件，B 端回放。对比回放位置和 A 端在同一发送方时刻的真实位置：

| 链路 | 要求 |
|---|---|
| 本机直连 | 位置误差 p95 ≤ 2 cm，D ≤ 30 ms |
| 100 ms RTT、20 ms 抖动、2% 丢包 | 位置误差 p95 ≤ 10 cm，最大 ≤ 40 cm；SURE 全部按序到达；QUICK 到达率 ≥ 99.9% |
