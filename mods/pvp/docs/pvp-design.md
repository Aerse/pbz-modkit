# pbzmp PvP 设计

目标：标题菜单多一个“多人游戏”，输入服务器 IP 创建房间或用房间码加入；房间里选武器、设回合数等；开局后两人传送到同一个封闭竞技场按回合对战，体验流畅。不依赖 UE4SS，全部是我们自己的 DLL。

## 总体结构

```
version.dll (main.cpp)      加载器 + tick 中枢：唯一的引擎 Tick 钩子，模块注册回调、投递任务、热重载
mp.dll (mods/pvp/src/)      PvP 模块，常驻
  net/    联机客户端：大厅协议 + 游戏通道（可靠/快速两条事件通道、字符串表、自适应延迟时间线）
  ui/     标题菜单按钮、连接/房间面板、对局 HUD、结算界面
  arena/  竞技场：生成/卸载、出生点、出界判断
  fight/  对手幽灵：移动/动画/技能回放、受击、招架、武器、伤害权威、倒下
  flow/   对局流程：按服务器阶段驱动 arena/fight/ui，保存屏蔽，赛后还原
server/pbzmp_server.py      大厅 + 转发服务器（UDP，单端口，可公网部署）
```

协议：docs/pvp-protocol.md（大厅）、docs/pvp-netcode.md（游戏通道）。客户端 API：mods/pvp/src/net/net.h。

## 关键决定

- 两种连接方式，net.h 对上层一样：
  - 中转服务器（默认）：两边只需连服务器 IP，NAT 不用打洞，延迟多一跳但稳定。
  - Steam 联机：房主建一个 Steam 大厅（大厅数据里放房间码），房间逻辑在房主本机跑（net/room_server，中转服务器的 C++ 版），数据包走 SteamNetworkingMessages（能直连就直连，否则走 Valve 中继）。不用自己架服务器，但房主退出房间就没了，不能崩溃重进。
- 各自世界、防守方权威（与 Phantom Pact 同思路，代码自写）：每个客户端只模拟自己的真人，对手是本地生成的幽灵角色。对手的攻击在我这边由幽灵用真实技能打出，命中与否、伤害多少由我的游戏判定，我扣血后把血量广播出去。
- 不走游戏自带的死亡流程：对局期间真人 Health_Min = 1，血量到 1 视为倒下，由我们播放倒地、禁止操作，等回合重置。这样不会触发复活点、刷怪和存档。
- 对局期间屏蔽存档（PBZSaveLoadSubsystem::EnterSaveVeto / ExitSaveVeto），赛后传送回原位置。
- 已知限制：进过竞技场之后，存档文件的写入一直拦截到游戏重启（fileguard，mp 卸载后也保持）。赛后 ExitSaveVeto 会触发一次存档，那时的世界状态来自竞技场关卡，不能写进玩家存档。要恢复单机存档，重启游戏。
- 竞技场是我们自己拼的封闭场地，坐标固定，两边一致；不复刻任何其他游戏的地图。

## tick 中枢（main.cpp）

- 加载器在游戏初始化后（对象数 > 50000）替换 UGameEngine::Tick（vtable 0x14b1b3900 槽 0xd2），之后谁都不再直接改 vtable。
- 模块导出 `PbzInit(const PbzHost*)` 拿到接口：addTick/removeTick（每帧回调）、post（下一帧执行一次）、log、dir。见 src/pbzmp/host.h。
- 每个回调都在 SEH 保护下运行，崩溃的回调记日志后摘除，不拖垮游戏。
- 热重载：`run X` 时如果旧的 X 还在且导出了 `PbzUnload`，先在游戏线程调用它、摘掉它的回调和待办任务，再卸载旧 DLL。`stop X` 只卸载。没有 PbzUnload 的老模块保持旧行为（不卸载）。
- 启动时读 `autorun.txt`，每行一个模块名，依次 run。发布版只写 `mp`。
- 多开：设置了 PBZMP_DIR 时，单实例互斥量名按目录名改成唯一的，可以同时开多个实例。

## 界面（mp/ui）

- 标题菜单：在 WB_StartMenu_V2_C 的按钮列里加一个“多人游戏”按钮（复制现有 W_MenuButton_V2_SelectedVersion_C 的样式），放在“设置”上面。
- 点击后开“多人游戏”面板：连接方式（中转服务器 / Steam 联机）、服务器地址和端口、服务器密码（Steam 模式隐藏）、昵称、[创建房间]、房间码输入、[加入房间]、[返回]。连接中、失败原因（版本不符、密码错误、房间不存在、已满、已开始、超时）都显示在面板里。地址、端口、昵称、密码和连接方式在创建/加入时存到 mod 目录的 mp_settings.txt，下次自动填好。
- 崩溃重进：比赛中每 5 s 把房间码、token、slot 和时间写到 mp_session.txt。重启游戏进标题后，如果这个文件不超过 110 s，就用旧 token 重新连回房间（服务器给比赛中的掉线成员保留 120 s 座位），然后直接传送回竞技场。重连失败显示“上一局已结束，无法重新连接”。正常离开房间会删掉这个文件。
- 进房间后是房间面板：房间码（大字）、成员列表（昵称、武器、准备状态、胜场、网络延迟）、武器选择（DT_WeaponData 里全部 25 把玩家武器，不要求存档里已拥有，每页 7 张卡片，左右箭头翻页）、房主可改回合数（1/3/5/7/9）、单回合时限（不限/60/90/120/180 秒）、伤害倍率（50%–200%）；[准备]/[取消准备]、房主 [开始]、[离开]。
- 从标题菜单开局时，先读“继续游戏”的存档进入世界，进世界后直接传送进竞技场，不需要玩家自己走到哪里。世界里也可以用 F7 打开同一个面板。
- 对局 HUD：顶部比分和回合（如 1 : 0，第 2/3 回合）、倒计时、对手名字和血条（他的真实血量）、延迟。count 阶段中间显示 3、2、1、开始。end 阶段显示“本回合胜利/失败/平局”，over 阶段显示比赛结果和比分，8 秒后回到房间面板。
- 所有输入都是玩家自己的鼠标键盘。我们从不模拟输入、不抢窗口焦点；自动测试通过直接调用 UE 函数（设置文本、调用点击处理函数）驱动界面。
- 显示面板时 SetInputMode_UIOnlyEx + 显示鼠标，关闭时 SetInputMode_GameOnly。

## 竞技场（mp/arena）

- 我们自己用游戏的环境模型拼一个封闭场地：直径约 35 m 的平整地面，四周高墙围住（高度跳不出去），场边有柱子、台阶等少量掩体，风格贴合本作。不复刻其他游戏的地图。
- 放在所有地图的上空远处（固定世界坐标，两边一致），远离任何地形和 NPC。光照用世界本身的天光。
- 出生点：slot 0 和 slot 1 相距 12 m 面对面。每回合开始重置到出生点、回满血和架势、清掉状态效果。
- 掉出场地（低于地面 5 m 或在墙外）：传回出生点并记一次出界（不判负）。
- 对局开始前记录真人的位置、血量；整场结束（或断线、离开房间、卸载模块）时传送回原处、还原血量，删除竞技场。
- 进竞技场前清除对真人的仇恨，对局中附近的敌人不会出现（场地在高空且远离地图）。

## 对战同步（mp/fight）

- 对手幽灵：本地生成一个 PBZCharacter_Player（和玩家同类），去掉相机组件、加锁定点组件、Health_Min = 1（本地打不死），属性用对手开局时发来的快照（攻击力 × 伤害倍率）。
- 敌对：幽灵和真人互相 SetFactionRelationOverride(…, 2, true)，结束时 ClearFactionRelationOverride。
- 每帧发本地状态（net::State）：位置、速度、输入方向、朝向、移动模式、血量/架势千分比、当前蒙太奇和进度、武器是否出鞘、动画状态字节；ext 里放运动匹配需要的轨迹数据。
- 幽灵回放：位置走时间线插值（net::Sample），用 AddMovementInput 跟随（误差大时滑行，极大时瞬移）；蒙太奇在收到的进度上播放并纠正漂移；跳跃、冲刺用游戏本身的动作。
- 技能：本地激活的技能发 `M <技能类 id> <yaw>`，幽灵用 TryActivateAbilityByClass 真的放出这个技能，所以命中判定、伤害、受击、格挡都由防守方自己的游戏算（防守方权威）。
- 受击：防守方把自己的受击状态发 `H <标签>`，攻击方的幽灵播放同样的受击。幽灵的身体只听远端；本地打中幽灵只有特效和音效，幽灵是否硬直以远端为准。
- 招架：防守方的游戏判定格挡成功时发 `V parry`，攻击方本人真实地吃到架势伤害和重硬直。
- 血量：每个人只看自己的真实血量。幽灵血条显示对手的真实血量（State.hp）。
- 倒下：对局中真人 Health_Min = 1。血量到 1 视为倒下：播倒地动作、禁用输入，调用 net::Dead(round, 最后 8 秒内打中我的人)。不走游戏的死亡流程。
- 武器：开局时按房间里选的武器给真人装上（SetSlotWeapon），对手的武器通过 `W <武器配置 id> <出鞘>` 同步到幽灵。

## 对局流程（mp/flow）

按服务器的 phase 驱动：

| phase | 客户端动作 |
|---|---|
| lobby | 显示房间面板 |
| load（第 1 回合） | 记录原位置/血量，EnterSaveVeto，生成竞技场，装备武器，生成幽灵，传送到自己的出生点，回满状态，然后 ArenaReady |
| load（之后的回合） | 传送回出生点，回满状态，清效果，ArenaReady |
| count | 显示 3、2、1，禁用攻击和移动 |
| fight | 放开输入，开始同步战斗；本地倒下就报 Dead；每 250 ms 报一次 Hp |
| end | 显示本回合结果，禁用输入 |
| over | 显示比赛结果，8 秒后回 lobby：传回原位置，还原血量，删幽灵和竞技场，ExitSaveVeto |

离开房间、断线、卸载模块：立即执行 over 之后的清理。

## 测试

- 服务器：server/test_server.py 单元测试（协议、阶段、回合、超时、去重、限流），可用 `--loss --delay --jitter` 模拟坏网。
- 网络层：nettest 的两档链路指标（见 pvp-netcode.md）。
- 游戏内：每部分有自己的开发模块单独测；界面用截图（HighResShot）检查；全部通过 UE 调用驱动，不碰鼠标键盘。
- 双开联调：本机两个实例 + 本地服务器。A 通过界面调用创建房间，B 用房间码加入，准备、开始，用驱动脚本自动移动和出招打完一整场，检查：同步误差、回合与比分、结算、赛后回到原位、存档没被改。然后加坏网参数再跑一遍。
- 测试实例：`tools/launch.ps1 <目录名>` 启动，小窗口、最小化、静音，不抢焦点。
